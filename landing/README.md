# Landing

Static public site of Abastevo (`https://abastevo.com.br`): home, guides,
calculators, tutorials, legal pages and the browser search used by the static
portal. Content is pt-BR first. The home, the about and editorial policy
pages, the calculators and a set of guides also ship in `en` and `es`, under
[decision 026](../docs/decisions/026-multilingual-public-site.md) and
[decision 027](../docs/decisions/027-ai-reviewed-landing-translations.md). The
[multilingual contract](../docs/product/landing/organic-growth-i18n-plan.md)
owns the locale, hreflang and translation rules. It is plain HTML/CSS with optional
TypeScript enhancement; it never calls a database and only the optional
contributors list calls the Abastevo API. The station/price portal pages
themselves are generated by the backend (`cmd/portal*`), not here.

## Layout

| Path | Contents |
|------|----------|
| `static/` | Authored pages (`index.html`, `privacidade/`, `termos/`, `excluir-conta/`, `como-usar/`, `contribuidores/`, `404.html`), `robots.txt`, `llms.txt`, `site.webmanifest`, `.well-known/security.txt`, `_headers`, `_redirects`, and the one IndexNow key file (`<32 hex>.txt`, whose content is its own name). The key is public; the build fails without exactly one. The web tier repeats `robots.txt` byte for byte, so change both together. |
| `static/assets/` | `styles.css` (design tokens), self-hosted fonts with OFL notices and `provenance.json`, brand icons, art and app images. |
| `content/` | `manifest.json` (page registry) plus Markdown for `guias/`, `ferramentas/` and `paginas/`. |
| `src/` | `main.ts` (progressive enhancement), `search.ts` (portal search), `tools.ts` (calculators), `contributors.ts` (live contributors list), `tutorial.ts` (lesson data validation). |
| `scripts/` | `build.mjs` (render, fingerprint, sitemap), `check.mjs` (artifact verification), `content/` (manifest loader, Markdown renderer, layouts). |
| `prototype/` | Synthetic portal page prototypes; tested, not emitted. |
| `tests/` | Node test runner suites. `dist/` is the gitignored build output. |

## Commands

```sh
npm ci
npm run typecheck
npm run build        # dist/
npm run check        # dist integrity, SEO, JSON-LD, links, headers, budgets
npm test
```

`build.mjs` options: `--origin <https-origin>` (default
`https://abastevo.com.br`), `--store-state prelaunch|published`, `--store-url
<Play URL>` (required when published; must be the `com.anpfuel` listing),
`--out-dir <dir>`, `--api-origin <https-origin>` (or `ABASTEVO_API_ORIGIN`;
empty keeps the contributors list disabled). `check.mjs` accepts `--origin`
and `--dist-dir`. `make quick-verify` runs all four npm steps when `landing/`
changes.

Test-only build options: `build({ enableLocales: ['en', 'es'],
translationsDir, messagesDir })` overrides the `enabled` flags of
`contracts/i18n/locales.json`, the translations directory (default
`content/translations`) and the dictionary directory (default `content/i18n`).
Production reads the registry flags. A locale is emitted only when its flag is
on, its dictionary is `reviewed` and the page is `reviewed`.

## Content pipeline

- Every page is registered in `content/manifest.json`. Guides, category hubs,
  calculators and `/sobre/`, `/politica-editorial/` are generated from
  Markdown front matter (`title`, `description`, `slug` = file name,
  `category`, `tags`, `datePublished`, `dateModified`, optional `headline`,
  `summary`, `related`). The build fails on invalid front matter, unknown
  categories, duplicate slugs or links to routes that are neither landing
  pages nor known portal routes.
- The Markdown subset is rendered in-house and HTML-escaped; raw HTML is never
  passed through. Images need alt text. An app capture is written as
  `![alt](/assets/app/<feature>-<NN-slug>-720w.webp "caption")` and must be
  listed in `static/assets/app/provenance.json`: the renderer adds the 9:16
  dimensions and the `srcset`. Image lines that follow each other without a
  blank line render as one strip.
- A tutorial chapter is `static/como-usar/<slug>/index.html` (authored HTML)
  plus `lesson.json` (its steps, validated by `src/tutorial.ts`). A step
  either shows a capture, with the highlighted control measured on the
  1080 × 1920 master, or is `textOnly` with the reason no capture exists.
  Captures and quoted app labels follow the
  [capture contract](../docs/assets/app-tutorial/CAPTURE_CONTRACT.md).
- `sitemap.xml` lists indexable pages only, with `lastmod` from front matter or
  the manifest (never the build time).
- `npm run build` emits `dist/assets/search.<hash>.js` and the same bytes as
  the stable `dist/portal-search.js`, which the portal worker reads through the
  landing `current` link (`ANPFUEL_ENTERPRISE_PORTAL_SEARCH_JS`). The browser
  loads one static regional shard at a time.

## Delivery

`release-staging` builds the landing with `--origin https://abastevo.com.br`,
copies `admin-web/dist` into `admin/` and `business-web/dist` into `empresas/`,
and ships the tarball as a layer of the signed release. The deploy agent
extracts it and switches the `current` symlink; rollback is the previous
release directory. On staging, response headers and cache rules come from
`infra/caddy/staging-web.Caddyfile`. For a Play Store launch, build with
`--store-state published --store-url <listing>` and re-run `check` and tests.

## Rules

- Essential content and navigation work without JavaScript; scripts only
  enhance. No inline scripts, no framework, no runtime dependency, no remote
  fonts or CDNs. TypeScript `7.0.2` is the only dev dependency.
- Assets are content-hashed and immutable; HTML revalidates.
- Render untrusted data with `textContent`; calculator inputs never leave the
  browser.
- Do not ship personal data, real contributor locations or production photos.
