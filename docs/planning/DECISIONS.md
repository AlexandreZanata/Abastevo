# Decision log

Status language: ADOPTED = planning baseline within requested scope, not implemented; ASSUMPTION = usable provisional default with a verification gate; PENDING = must be resolved by the stated task before dependent behavior ships. Do not pause unrelated planning for an unresolved choice.

- **D01 — Runtime versions (SELECTED during P01; evidence recorded).** Initial alternatives were supported Go/PostgreSQL/PostGIS releases compatible with available images/tooling. Exact selections/pins now live in [TOOLCHAIN](../backend/TOOLCHAIN.md), backend/go.mod and infra/compose.dev.yml; [P01 evidence](history/P01_FOUNDATION_EVIDENCE.md) records their local validation. Why: repeatable builds and operational maintenance. Tradeoff: deliberate maintenance versus accidental upgrades. This workflow revision does not independently revalidate external support/security claims; dependency maintenance and release checks remain required.
- **D02 — Deployment capacity (ASSUMPTION, P08-T07).** Options: one 16 GB VPS, smaller measured pilot, managed database. Recommend 16 GB single-host starting hypothesis, verified by load/restore evidence. Tradeoff: simple operations versus shared failure/resource domain. Resolve before G09 capacity claim; no vendor purchase during planning.
- **D03 — Mobile signatures (ASSUMPTION, P03-T01 and P10-T03).** Options: P-256 Keystore, Ed25519 with proven support, bearer-only anonymous identity. Recommend P-256 and a narrow RFC 9421 profile for current Android reach. Tradeoff: challenge/protocol complexity; support/hardware quality varies. Freeze standard byte vectors before backend auth and verify real devices before app release.
- **D04 — Price precision and naming (ADOPTED, P02-T01/T02).** Options: cents/legacy PREMIUM; milli-BRL and explicit ADDITIVED/units. Recommend exact milli-BRL plus raw source decimal, explicit unit and compatibility fixture; no float. Tradeoff: requires adapter/Room review later. Unknown higher precision quarantined; fixtures before import.
- **D05 — Geocoder (PENDING, P02-T07).** Options: commercially permitted provider, licensed coordinate dataset, reviewed manual pilot catalog, own geocoder later. Recommend provider/dataset permitting pilot volume with cache/attribution/global quota; missing coordinates remain unknown. Tradeoff: cost/coverage/licensing versus operator burden. Public Nominatim is not assumed valid for national bulk lookup. Resolve provider terms before live use; fixtures permit independent development meanwhile.
- **D06 — XLSX parser dependency (PENDING, P02-T04).** Options: bounded standard ZIP/XML reader or maintained streaming library. Recommend evaluate real source files, uncompressed limits, malformed input and memory before choosing minimum solution. Tradeoff: library surface versus custom parser maintenance. Record license/security/build impact before adding dependency.
- **D07 — Retention/legal purposes (PROPOSED, P07-T05).** Options: conservative short periods versus longer reviewed cases. Recommend inventory in SECURITY_PRIVACY with 24 h precise payload cap, 14-day sanitized media and bounded audit/backup periods. Tradeoff: less forensic replay versus minimization/cost. Responsible operator/legal review closes lawful bases, rights deadlines and processor terms before pilot/G09.
- **D08 — Consensus defaults (ASSUMPTION, P06-T04 and P10-T09).** Options: exact groups with conservative quorum or fuzzy clustering. Recommend deterministic consensus-v1 and 48 h anchor expiry, no purchase signals. Tradeoff: more LOW/UNKNOWN and exact-value splitting in exchange for explainability. Synthetic golden calibration before G09; labelled pilot evaluation before tuning a new version.
- **D09 — License and contribution terms (MIT ADOPTED; future PENDING).** Options: keep MIT; Apache client/new code; AGPL backend. Recommend retain MIT throughout MVP; DCO before external backend contributions; ownership/dependency review before changes. Tradeoff: permissive reuse versus later hosted-copy competition. Any change requires explicit human decision; old MIT rights persist. No current task is blocked by keeping MIT.
- **D10 — Brand and paid offering (PENDING, after community pilot).** Options: retain current identity, validate Postô, another cleared name. Recommend provisional name only and sell hosted convenience after demand evidence. Tradeoff: no early rebrand momentum but no package/mark churn. Decide before public branding/billing, not before backend engineering.
- **D11 — Recovery objectives (ASSUMPTION, P08-T04).** Options: daily encrypted dumps with RPO24h/RTO4h versus WAL/PITR. Recommend first, if pilot operator accepts measured loss/downtime tolerance. Tradeoff: possible up-to-day write loss versus lower complexity. Restore proof and explicit objective acceptance before G09; stronger claims require new tested design.
- **D12 — First pilot and API support window (PENDING, P09-T03/P10-T09).** Options: one municipality/small cohort versus broad launch. Recommend one adequately geocoded city/cohort and admission caps; choose size/duration from capacity and moderation coverage. Tradeoff: limited geographic reach but measurable trust/cost. Record minimum v1 support/deprecation window before publishing Android clients; do not silently remove an API used by released apps.

- **D13 — Phase delivery and CI cadence (POLICY ADOPTED; activation PENDING P01-T13…T17).** Options: full suite/PR per microtask, phase delivery with focused local checks and quick CI, or defer all checks to release. Choose phase delivery per [ADR-013](../adr/013-fast-phase-delivery.md): task issues/commits, phase branch/PR, wiki mirror per merged phase, full certification at P09/G09. Why: reduce repeated work while preserving immediate critical tests and guarded integration. Tradeoff: broad cross-system failures may surface at candidate certification; task acceptance and the explicit full matrix remain mandatory. Resolve automation and protection migration before P02; existing CI remains binding until G01-FLOW.
