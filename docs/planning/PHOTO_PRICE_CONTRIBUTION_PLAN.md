# Android photo price contribution plan

State: PREPARATION_LOCAL_DONE / IMPLEMENTATION_PLANNED, 2026-10-07. Owner: P37-T01–T03, following P34–P36 source integration. This record prepares the user's requested flow and private real-photo evaluation; it does not certify OCR, proximity, uploads, training storage or production. Develop one bounded task at a time on maintained `dev` under ADR-020. Backend contracts and critical tests precede affected Android consumers. iOS remains deferred.

## Accepted product decisions

- Open the camera only after the selected station's proximity requirements pass. Initial maximum distance: **150 metres**, confirmed by the user. This is a radius around a reviewed station point, not proof of being inside its property boundary.
- Capture, recognize locally, review a large photo, optionally zoom/pan/crop locally, recognize the resulting crop again, edit/remove fuel rows, then explicitly submit. No photo upload during capture, zoom, crop or OCR.
- Initially show only recognized fuel rows with usable prices. Each row has the existing fuel icon, name/unit, editable price and an accessible X/remove action, arranged vertically. One or several fuels are valid; no complete price list is required. Blank values and removed rows are excluded.
- No payment-method or loyalty-program inputs in this flow. Preserve price-condition truth internally; restricted/ambiguous prices cannot silently become STANDARD.
- Optional AI-training consent, off by default. Operational photo copies expire within 24 hours. An explicitly authorized, minimized training copy may have **permanent storage with no automatic TTL**, subject to the continuing purpose and applicable revocation/erasure obligations. The [consent amendment plan](../security/AI_TRAINING_IMAGE_CONSENT_PLAN.md) owns this exception; current runtime policy has not changed.

## Behavior contract — document before implementation

- **B-BR-PC01 — Camera eligibility:** station has a canonical UUID and usable reviewed coordinates; obtain location only for this action and classify freshness, accuracy, clock and OS mock signal with the existing P16 contract. Missing/denied/stale/inaccurate/mock/unknown evidence does not open the camera. No background tracking. Existing anonymous reads/manual lookup remain usable. A finite, nonnegative measured distance at most 150m is necessary; a distance from a stale list alone is insufficient. Preserve existing frozen freshness/accuracy bounds and document the uncertainty decision before code.
- **B-BR-PC02 — Local-first image processing:** preserve actual capture time and immutable source generation. Sample-decode off the UI thread, apply EXIF orientation before coordinate mapping, display a large image, permit pinch zoom/pan and adjustable crop, and retain fuel labels with prices and visible restrictions. Cropping away a condition does not erase an ambiguity detected in the original. Encode the final crop with the existing P15 JPEG/dimension/attempt budgets; do not increase budgets by default. No original/GPS metadata goes to the server. Delete superseded temporary files and do not reset expiry on crop/retry.
- **B-BR-PC03 — OCR as a proposal:** recognize pixels into text blocks with positions; associate label, unit and neighboring price by spatial row/column. Accept comma/dot and supported two/three decimal digits into exact integer milli-BRL. Distinguish R$/L from pump total, litres, dates, address numbers, serials and watermarks. A zero, uncertain variant, unsupported premium, multiple conflicting candidates or restricted-price ambiguity requires correction/retake rather than an invented row. Never choose the smallest number automatically.
- **B-BR-PC04 — Reviewed subset:** render recognized, supported fuel rows only. Show one row per unambiguous product/price; preserve edits/removals through recomposition, rotation and crop reanalysis. A new crop may suggest changes but must not overwrite user edits or restore removed rows silently. Allow an explicit add-fuel action when OCR misses a visible product; this does not populate every enum automatically. Empty recognition presents crop/retake and manual addition with the retained photo.
- **B-BR-PC05 — Confirmation and truth:** the explicit confirmation attests the selected rows and advertised default price without exposing payment inputs. If the image only offers a cash/app/loyalty price or conflicts across conditions, request a photo/crop of the default price or a corrected supported default-price selection. Exclude unsupported conditional rows from this simplified journey. Existing condition-aware routes retain their contract; do not rewrite CASH/APP/LOYALTY to STANDARD. Surface an explanation rather than guessing.
- **B-BR-PC06 — Durable submission:** accept at least one valid, nonblank row, validate every remaining row, then persist a single review snapshot with stable per-row submission IDs and one media reference. Preserve original capture time; never relabel old images as new. Handle disabled/denied/expired/failed enqueue results truthfully. Double taps, process death and retries cannot create duplicates. One row's error cannot report all rows accepted. Server validation/publication remains distinct from local queueing.
- **B-BR-PC07 — Optional training use:** no preselected consent, bundled mandatory acceptance or trust/payment advantage. Record the version and permission applicable to each image; check current server consent again before promotion, export and training. Consent refusal never blocks an otherwise valid contribution. No training reuse of the historical evaluation corpus merely because its owner requested app tests.

Use cases: **BUC-PC01** station/context → eligibility → capture or recovery instructions; **BUC-PC02** recognize → zoom/crop → re-recognize → edit/remove/add → confirm subset; **BUC-PC03** durable enqueue → upload → owner-visible pending/accepted/rejected/retry/expired status; **BUC-PC04** optional consent → private training promotion → revoke/delete.

Portuguese UI copy to validate in the existing design system:

- Primary action: `Contribuir com foto`.
- Outside: `Para contribuir com foto, você precisa estar a até 150 metros deste posto. Aproxime-se e tente novamente.`
- No reliable fix: `Não foi possível confirmar sua localização. Ative a localização e tente novamente.` Give the specific permission/accuracy recovery action when known; do not describe every failure as outside.
- Review: `Confira os preços da foto` / `Aproxime e recorte para destacar os combustíveis e preços` / `Você pode enviar apenas os combustíveis que quiser. Valores em branco não serão enviados.`
- No detected rows: `Não reconhecemos preços com segurança. Recorte a placa, tire outra foto ou adicione um combustível.`
- Ambiguity: `A foto mostra um preço com condição ou um combustível que não conseguimos identificar. Confira o preço padrão ou tire outra foto.`
- Submit: `Confirmar e enviar` with selected-row count; queued: `Aguardando envio`, never `Publicado`.

### P37-PC02 — Bounded image recognition adapter

Reuse the existing OCR port and pure parser, add the native pixel recognizer behind it, with cancellation and generation-based late-result rejection. Prefer an on-device Latin-script engine; no new server AI service is required for this MVP. Evaluate ML Kit's Play-Services model against the bundled model. The [official Android guide](https://developers.google.com/ml-kit/vision/text-recognition/v2/android) distinguishes `com.google.android.gms:play-services-mlkit-text-recognition` (downloaded model) from `com.google.mlkit:text-recognition` (bundled model). [Installation guidance](https://developers.google.com/ml-kit/tips/installation-paths) explains availability/offline implications. Correct the existing DI comment; do not claim Apache-2.0 licensing based on sample-code licensing. Record dependency need, exact supported version, SDK terms/license, transitive/security review and measured release-size impact before addition.

Separate native decoding/OCR blocks from pure spatial association and exact money parsing. Test synthetic labelled blocks for swapped rows, separator loss, multiple columns, conditions, generic diesel, premium/additivated distinction, zero, pump total and watermark rejection. Test model not installed/download failure, no Play Services, cold/offline availability, recognition failure/cancellation and stale results. Real images remain private external fixtures, never Gradle APK assets or repository fixtures.

Exit: twelve-case device benchmark with actual recognized rows/timing, explicit manual fallbacks, and no fabricated baseline. Existing integer-money and fuel-wire contract tests pass.

## Private evaluation protocol

1. Use `combustiveis/teste_ocr/README.md` and the twelve-image ground truth. Run identical inputs through the actual Android adapter in a debug/instrumentation-only harness with no network upload, no fake location claims and no release import/gallery bypass. The current APK has no such harness; staged fixtures do not mean OCR ran.
2. Evaluate full image and user crop retaining fuel labels. Record exact product+amount matches, missed rows, false rows, unsupported/conditional/zero handling, edits, latency and peak additional memory. Ground truth includes ambiguous fuel/null and unsupported premium on purpose. Do not score an unsafe guess as a successful detection.
3. Extend to at least 100 manually verified, stratified images from the selected corpus, plus consent-free synthetic no-price/invalid cases. Include LED, physical digits, worn/missing separators, reflection, shadow, angle, distant/partial signs, one fuel, multiple fuels, three decimals, zeros and watermarks. Deduplicate by hash and group near-duplicate station/sign/scene photos before tuning/evaluation splitting; 1,219 hashes are not 1,219 independent situations. Keep annotations/images private.
4. Proposed benchmark targets to freeze after the first baseline: clear supported rows ≥99% precision and ≥95% recall; zero fabricated rows from non-price numbers in the annotated challenge set; no zero/unsupported/conditional price silently submitted as STANDARD. Report denominator, families and fallback rate. The twelve-image smoke is not statistical acceptance. Measure cold/warm p50/p95 OCR and memory on POCO; existing P15 memory limits remain hypotheses until measured on required devices.
5. Then use the genuine camera to photograph a displayed selected image: this tests optics/reflection/perspective locally, not station presence or current prices. Historical test images must never update a real station's live price. Keep this isolated from network-capable contribution paths; do not trick the geofence to obtain the photo.
6. Finally, with the user physically near a reviewed real station and an authorized staging test target, test outside >150m, boundary, inside ≤150m, permission denied, stale/inaccurate fix, airplane mode and camera cancellation. Field measurements and controlled synthetic boundary tests are separate evidence. Re-photograph the current sign; compare the real review with the sign, submit only the owned staging cases and verify 1/2/3-fuel omission/retry/status. No location spoofing or production publication.
7. Test consent unchecked/checked, restart/offline queue, revoked before promotion, promotion racing revocation, account deletion, expired operational evidence, storage failure and restore. Use synthetic pictures to prove backend/backup deletion; retain only aggregate evidence in Git. Real device media test records stay private and expire according to the tested app policy; external source corpus stays under user control.
