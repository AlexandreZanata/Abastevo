## Observed before any change

- The app's map already accepts a local hand-off, `MapRouteTarget`, from the
  station screens: `Point` opens the route at a coordinate; `Address(query)`
  opens the route sheet with the destination search filled and "Address
  matches require user selection" — the driver picks a result of the
  on-device offline search before the native engine computes the route.
  `fromStationQuery` parses a "lat,lon" text into a `Point`.
- A mission plan's destination is a free text or a unit identifier; units have
  no coordinates (only an optional IBGE municipality code) and the device holds
  no unit name. No trip carries a destination of its own; only the mission a
  trip's start names (EMP-TRIP-023 reference) has one.
- The guidance service is local and has no network client; no enterprise
  screen builds an `Intent`. On the first draft the device had no tracking
  producer; after the coordinator-requested merge of the F4 head `19e681a3`
  (EMP-GPS-002/003) the trip screen hosts the tracking card, whose session the
  driver starts and stops with its own taps and which follows the trip's
  finish, pause and cancellation — the navigation path calls none of it.

  `AnpNavGraph` sets `pendingRouteTarget = MapRouteTarget.Address(query)` and
  opens the MAP tab (the station hand-off path). Six strings × 8 locales
  (`enterprise_route.xml`, generated by `f4-logs/route004-scripts/gen_route_strings.py`).
- Tests: `EnterpriseTripNavigationTest` (domain, 3),
  `TripNavigationIsolationTest` (app source guard, 2),
