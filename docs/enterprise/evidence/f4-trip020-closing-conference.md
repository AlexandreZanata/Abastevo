## Decision on the trip ↔ fueling/expense relationship (task question)

**Device-local, with an explicit retained item** (EDR-339). The server keeps
`trip_id` RETRY/UNAVAILABLE for expenses (EDR-289) and has no fueling trip
reference (FUEL-002 retained); a soft reference per BR-OFFL-007 would need
both owners to accept it, hold it for review and handle orphans — two
owners' intake changes beyond this task. The conference only needs the
driver's own records to check before submitting, which the device has: it
groups, on the device only, the partition's fuelings and expenses of the
trip's vehicle declared between the trip's start and its finish. Nothing is
sent as a link and nothing is added up. Retained: the server-side soft
reference (owners FUEL/EXP) and, with it, a conference the panel can show.

On "submits the correct revision": the conference queues the first
submission exactly as TRIP-005 (revision 1, depending on the finish) and
refuses a second. A resubmission after a return must name the returned
revision (EDR-236); the device cannot learn of a return (TRIP-004/005 retained
the author's own review read), so choosing a revision would be a guess —
retained (EDR-341), not faked.

## Named negatives → tests

| Negative / acceptance | Test(s) |
|---|---|
| Foreign attachment | domain `a photo of another record never counts…` (a photo owned by the fueling but targeting the expense documents neither); records of another vehicle (domain, flow) and another organization's partition (flow: B's parking absent) never appear |
| Duplicate cost | domain: a duplicated fueling entry counts once; amounts per item only, no total (`paidCentavos` per item; presentation: no "Total"); expenses are `expense.submit` DIRECT records only, a fueling's projected expense is never an item (FUEL is not a device category, EDR-337) |
| Unreadable evidence shown as verified | domain: a null index makes every item `UNREADABLE`, never `AVAILABLE`; `FILE_MISSING` is `MISSING`; presentation: "não é possível ler" and no "guardado"; no "válido" text |
| Offline approval | the conference has no decision action; "the company decides" note; submission only queues `trip.submit` (flow test), whose acceptance follows its own receipt (TRIP-005) |
| Missing / pending / available | domain: no photo → missing, saved/declared → pending, stored → available, per item; record states from each receipt (saved, accepted, refused with reason) |
| Correct revision | flow: the offered submission is revision 1 depending on the finish; a second mark queues nothing (`ALREADY_SUBMITTED`); a marked trip shows `ALREADY_MARKED` with no revision; resubmission after RETURN retained (EDR-341) |
| Unreadable related lists | flow: an unreadable fueling list sets `relatedUnavailable`, never hides the trips; domain: a null list is "possibly incomplete" |
| Interval | flow and domain: before the start and after the finish are excluded; an open trip confers everything since its start |
