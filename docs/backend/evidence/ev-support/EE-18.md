Before behavior: offline users browse validated public charging
snapshots with source/profile/license/revision metadata, imported as
atomic Room generations with resumable validated deltas. Corrupt hashes,
wrong base/source/origin/schema, tombstones, disk bounds and no-store
are enforced before any write, so a failed pack leaves the committed
generation — and every fuel/history/private row — untouched. Recovery:
discard only the uncommitted public generation; never wipe the user DB.

## Delivered

- `domain/charging/ChargingSnapshot.kt`: strict DTOs
  (`ChargingPlace/ConnectionGroup/Page/Coverage/PackMeta`) with closed
  connector/current/access enums; unknown wire values decode as UNKNOWN
  with raw wording retained, coordinates stay nullable, counts are
  non-negative, instants/origins/licenses validated.
- `data/remote/charging/ChargingSnapshotJsonCodec.kt`: strict decode of
  EE-09 pages/detail/coverage (≤100 rows, distinct ids, no private
  fields, typed counts); corrupt/oversize/foreign/private bodies throw
  `ChargingSnapshotUnavailable`.
- `data/remote/charging/ChargingSnapshotHttpClient.kt`: bounded anonymous
  reads (places pages with profile/revision/limit/cursor, detail,
  coverage) over MockWebServer-proven paths — no redirects/retry, 20 s
  call timeout, 1 MB body budget, `Cache-Control: no-store`, no response
  cache, cancellable transport, repeat-cursor refused.
- `data/local/charging/ChargingSnapshotImport.kt`: pure pack planner —
  admitted profiles only (`ocm-br-20261021-v1`, `pbe-2026-pdf-v1`;
  licensed-operator refused), origin/base/schema/license/manifest
  checks, per-page SHA-256 over raw bytes, duplicate/overlap refusal,
  10 000-place and 8 MB budgets, tombstone validation, coverage
  cross-check, resume cursor for interrupted deltas.
- `ChargingSnapshotPlaceEntity/MetaEntity`, `ChargingSnapshotDao`:
  (place_id, generation) rows plus per-pack meta (state/cursor/counts);
  `replaceGeneration`/`appendDelta`/`removePack` run in Room
  transactions (new generation → meta swap → old deletion → budget
  enforcement); tombstones invisible to reads until resnapshot clears
  them; licensed-operator data never has a path here.
- `MIGRATION_18_19` (additive: 2 tables + 2 indices), database v19,
  DAO provisioned, migration registered. Generated Room 19 schema
  cross-checked against the migration SQL (columns, keys, indices),
  then removed (repo tracks schemas only to v9; v10–18 likewise absent).
