Before behavior: the Go side admits versioned prepared batches through
module ports with bounded typed streams. Manifests verify by shape,
frozen profiles, recomputed content identity, input/output descriptors
and per-kind census; streams verify by bytes and hashes; entities
verify by order, recomputed source keys and assertions; decisions
reconcile outcomes. A late corruption, cancellation, close, duplicate,
changed reference, license or oversize returns nothing. Runtime
producers stay off until storage/publication gates pass. Recovery:
leave runtime off, refuse the batch.

## Limits

- This unit bridges prepared batches only. No storage (EE-07),
  publication, worker, app or runtime producers. Admission here is
  content verification (hashes/census/IDs), not source-rights grants
  (those stay user-declared per snapshot).
- Manifest content identity requires Go canonical JSON to match Rust
  ev-json-v1 byte-for-byte (sorted keys, compact, no HTML escapes);
  parity tests prove the match on both real batches. Any serializer
  drift fails closed (refusal, not silent acceptance).
- Raw source bytes/hashes in decisions are carried, not re-verified
  (source files stay private outside Git); stream and content hashes
  bind what the bridge reads.
- No device, no production, no deploy and no release acceptance is
  claimed.
