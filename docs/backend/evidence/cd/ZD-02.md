B-BR-CD-ZD-03: Given SIGTERM, readiness becomes 503 immediately while
liveness and normal traffic continue during a configurable 0–30s delay
(default 10s). Only after endpoint propagation does the listener close;
in-flight requests may finish within the independent shutdown timeout.

BUC-CD-ZD-02: Kubernetes sends SIGTERM, the process withdraws readiness,
continues accepting requests during propagation, gracefully shuts down, then
exits successfully. No request context is tied to the canceled signal context.
Worker dispatchers stop on that same cancellation; lease fencing/retry protects
interrupted effects. No queue/schema behavior change is authorized here.

Invariant: drain delay + shutdown timeout + 5s < termination grace. The reviewed
manifest will pin 10s + 10s + 5s < 60s (even max drain 30s fits).

B-BR-CD-ZD-04: A handler canceled by process shutdown must finalize its held
lease using a separate bounded 5s acknowledgment context. Completed effects
are acknowledged, interrupted handlers retain the existing retry budget and
delay, and no new claims start. Database failure or stale fencing still fails;
lease expiry remains the fallback. The process joins dispatchers before closing
its pool and treats signal cancellation as a clean exit.
