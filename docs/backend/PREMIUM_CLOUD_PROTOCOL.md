# Premium private cloud protocol v1

PRM02 opening; rules B-BR-PR06–PR12 and BUC-PR02/07. One account owns each record; local UUIDs remain unchanged and are scoped by owner (the same UUID in a different account never selects the first account's data). No tenant/fleet ownership.

Vehicles are typed version-1 records: local UUID, display name (1–100 Unicode characters, no controls), tank capacity in integer milli-units (positive, <=200000, multiples of 10 to preserve local two-decimal precision), canonical fuel/unit pair, existing cheapest/specific-CNPJ source, basic-alert switch, nonnegative sort order and archived flag. Legacy GASOLINE_PREMIUM maps explicitly to GASOLINE_ADDITIVED; true premium grade stays distinct. LPG_P13 is not a vehicle tank fuel; unsupported local records remain local and produce a recoverable import error. Archived vehicles count toward the existing three-record ceiling. Import never changes local IDs or allocates a fourth hosted vehicle.

Private commands resolve owner via session and require current signed contributor/key binding. Store locks owner/session/key before live capability check in the same transaction. Missing paid port fails closed. No deployable synthetic entitlement. Initial identical vehicle import converges; divergent existing UUID requires expected revision and explicit resolution. No automatic guest upload or account merge is implied. Consent, device proofs, common receipts and public owner APIs land in their owning tasks before any consumer is enabled.

PRM02-T02 allowlist: favorite key equals canonical station UUID; only currently active directory references can be newly selected. Missing/retired references are not recreated, and later reads can report unavailable. No backend following/favorite subscription implementation was found in this main-based source; this private set does not create free push/follow subscriptions. Maximum 1000 hosted favorites (source ceiling, not capacity evidence), one portable preferences singleton.

Portable preference v1 fields only: chosen state/municipality, exact fuel, supported locale and user-selected flag, show-price-history, nearest-search radius. Supported locale tags mirror AppLocales (pt-BR/en/es/fr/zh-CN/ru/de/ja or empty system default). State must be a Brazilian UF; municipality is an optional seven-digit IBGE code and requires a UF. All local sync/Wi-Fi/battery/permission/onboarding/auth/signing/purchase/location/photo/cache fields are excluded. Unknown fields and versions refuse; no generic JSON preference replication. Free local preferences/favorites are unchanged.

PRM02-T03 device references: server-generated random UUID, bound to owner + current session family + signing contributor/key + trusted server origin. They contain no hardware/ad identifier or independent bearer credential. Current signed account proof is required every command/pull; a device UUID alone grants nothing. At most three unrevoked device references per account across origins; a revoked/expired session cannot use its reference. Revocation is a free signed owner operation, preserves cloud/local records, and cannot be undone by restoring old device rows. Re-register with fresh proof to mint a new reference; old UUID remains revoked. Successful command transactions alone update last-success. Account deletion immediately revokes all references.

PRM02-T04 commands: at most 50 operations / 64 KiB canonical batch / 8 KiB per record, 600 new commands/hour and 10000 retained receipts/account; receipts retain 30 days, never silently evict within that window. Each UUID operation binds dataset, resource UUID, expected record revision, deletion flag, normalized payload, owner epoch and consent revision. Identical committed replay returns its original operation result; changed reuse conflicts. Owner-global revisions order changes; record revisions guard conditional writes. One SQL transaction owns the full batch and durable receipts; failure rolls everything back. Current device and paid capability are checked inside the transaction and again before commit; exact replay does not recover revoked authority.

Consent mask defaults OFF. The command envelope includes the current consent revision and refuses a disabled dataset; the opt-in/import user flow is PRM03-T03. No API caller can directly set a mask or epoch. Account deletion bumps the durable epoch and clears payloads/devices/changes. Record deletion nulls previous change payloads and writes an opaque erased-ID fence before removing content; old edits/UUID recreation cannot resurrect it. Receipts contain only operation/resource/result metadata, never retained old payload/name/credentials. Restored infrastructure must replay the separate external erasure ledger before serving; local epoch tables alone do not certify that operational recovery.

Vehicle removal uses the archived flag until the professional dependency/cascade-preview port exists; command hard-delete of a vehicle is refused. Free personal-data erasure is a distinct owner operation and does not imply business cascade semantics.

PRM02-T05 APIs: current account-session proof resolves owner; signed proof additionally protects device registration/revocation, commands and free erasure. Owner status, dataset pages, device pages and explicit cloud export/inventory are free; they never accept an account ID or restore credentials. Record pages are 20 by default / 100 maximum with authenticated owner/origin/dataset/epoch/schema-bound 15-minute cursors; responses are no-store without ETags. Export scope is the registered cloud datasets, not the existing contributor-only public-participation archive. Future professional/rule/snapshot datasets must register their own inventory/export/erasure ports before accepting data.

Free erasure nulls selected record/change payloads, preserves opaque anti-replay fences, disables the selected dataset consent and increments owner epoch before commit. Erasing all cloud data also revokes devices. It does not delete the free account or local data; account deletion independently invokes the same database privacy guards. Retained paid expiry data remains exportable while held; the 30-day exit/purge worker is completed with the retention task, not inferred from an API response.

PRM03-T01 change feed: owner-global committed sequence, current device/key/origin and enabled datasets only. First page captures a fixed high-water revision; later pages retain it, so interleaved writes appear in the next cycle without gaps. Each change includes its sequence and record revision; repeated delivery is safe for a client that applies only newer revisions. A signed 15-minute cursor binds owner/origin/device/schema and carries epoch/consent revision/last sequence/high-water. No cursor may select another account, device, dataset permission set or compacted history. An expired/compacted/erased cursor returns resnapshot-required, preserves pending local changes and never silently advances. New devices after compaction must obtain the PRM03-T03 consistent snapshot before requesting deltas.
